# Timetable Flow — Intuitiveness Scope

**Goal:** make the entire timetable flow — from first login to a published timetable — intuitive enough that a non-technical school secretary (often on a low-end Android phone) can build, fix, and share a timetable without training, support calls, or fear of losing work.

**North star — the user should always be able to answer:**

1. What state is my timetable in? (one answer, everywhere)
2. What should I do next? (every message leads to an action)
3. What just happened? (no silent changes, no silent losses)
4. Can I undo it? (destructive = explicit + scoped + reversible)

**Non-goals (out of scope):** new backend features (publish enforcement gate, PDF lib, notification service), redesigning the visual theme, exam timetables, and mobile app work. This scope is about the existing admin flow.

---

## Current state

The module has had real UX investment (see `TIMETABLE_UX_REVIEW.md`): undo delete, safe error messages, conflict highlighting, share drawer, mobile day tabs, onboarding checklist, fill progress. The remaining problems cluster into five themes:

| Theme | Symptom |
|---|---|
| **Trust killers** | Form wipes edits, destructive defaults, crash bug, silent reverts |
| **The form overrides the user** | Auto-swapped teachers, prefilled data, dead buttons with no reason |
| **Guidance dead-ends** | Problems listed with no path to a fix; contradictory readiness verdicts |
| **One concept, many names** | period/timeslot/lesson, 4 names for auto-fill, 3 readiness thresholds |
| **Mobile ergonomics** | Status wall crowds out the grid, sub-30px tap targets, frozen timestamps |

Plus a maintenance hazard: **13 dead components** with near-identical names to live ones.

## Phase 1 — One source of truth (~2–3 days)

> **Status: shipped** ✅ — readiness helper + vocabulary unified. Test: `utils/getTimetableReadiness.test.ts` (10 cases).

The biggest intuitiveness win: every surface answers "am I done?" with the same sentence.

### 1.1 Shared readiness model ✅
- Created `utils/getTimetableReadiness.ts` — one pure function returning `{ verdict, fillPct, emptySlots, label, nextStep, canPublish, isComplete }`.
- Verdicts: `no-structure → not-started → clashes → in-progress → almost (85–99%, 0 clashes) → ready (100%, 0 clashes)`.
- Rewired all four consumers:
  - `TimetableHealthPanel` — pill label, tone, next-step text and bar colour all come from the helper.
  - `TimetableStatusMeter` — now clash-aware (red when clashes) and rendered from `lg` up (was `xl`, so it was invisible on most laptops); shows a clash count.
  - `TimetableShareDrawer` — publish gate (`canPublish`) and a new verdict line use the helper; checklist split into **Before you share** (required) and **Recommended**.
  - `TimetableJourney` — "Check it" stop gained an amber **attention** state (no more green check beside "things to look at"); share stop copy unified.
- **Acceptance met:** at any fill level the four surfaces agree; a surface only says "Ready to publish" at 100% fill with 0 clashes.

### 1.2 One vocabulary ✅ (mostly)
- **Auto-fill** is now the single verb: `Auto-fill timetable` / `Auto-fill from weekly lessons` across `TimetableHealthPanel`, `TimetableMobileToolbar`, `TimetableAutoGenerateDrawer` (header, sheet title, primary button), `TimetableJourney`, `TimetableModeEntry`, and `page.tsx` menus.
- **Problem taxonomy:** `TimetableConflictsPanel` groups are now **Clashes** and **Coverage gaps & workload notes**; `TimetableSubjectInsights` says "N coverage gaps"; `TimetableHealthPanel` advisory pill and `TimetableConflictsPanel` badge say "N to review".
- **Share** is the one verb: "Share with teachers" / "Share again" / "Shared" across `TimetableHealthPanel`, `TimetableJourney`, `TimetableShareDrawer` and `page.tsx` menus/toasts.
- **Period vs lesson:** `TimeslotEditDialog` copy now says "period" ("Update this period's start time…", "across all grades").
- **Time format:** new shared `utils/formatClockTime.ts`; `WeekTemplateManager` now renders 12-hour times with no seconds.
- **Remaining:** (a) the `HealthPanel` advisory pill sums coverage gaps + workload notes into one "to review" count rather than splitting them; (b) the remaining "Add New Time Slot"/"time slot" strings live in **dead components** (`TimeSlotModal`, `TimeSlotManager`, `TimetableControls`, `TimetableGrid`) and disappear with Phase 5; (c) a few `console.error` messages still say "time slot" (not user-facing).

**Note:** Phase 3.1 (journey third state) was implemented early as part of 1.1.

## Whole-school view is opt-in (shipped)

The whole-school grid no longer renders by default when you land on the page. The default flow is now **open page → pick a class → edit that class's timetable**, with the whole-school grid one click away.

**Landing state (no class selected):** a "Choose a class" empty state in the grid area — quick class chips (up to 12) plus a "View whole school" button. The sidebar remains the full class list.

**"Whole school" toolbar button** (left of the title, `LayoutGrid` icon):
- From a class: switches to the whole-school grid, remembering the class. The button becomes "Back to {class}" while you're in the whole-school view, so toggling back is one click.
- The sidebar "All classes" item enters the same view (without the one-click return).
- Clicking any lesson chip inside the whole-school grid still jumps straight into that class.

**Implementation:** `schoolWideView` + `lastClass` state in `page.tsx`; grid selection is `!selectedGradeId ? (schoolWideView ? <combined grid> : <class picker>) : <class grid>`. Entering the whole-school view clears the class selection, so every scope-aware surface (status meter, health panel, share drawer) stays consistent — they already treat "no class selected" as school scope.

Mobile keeps its own panel and is unchanged.

## Design system

The whole flow shares one token layer in `utils/timetableTheme.ts` (`tt`). The polish pass replaced ad-hoc values with these tokens — keep using them.

**Voice:** sharp-edged (border-radius 0, enforced by `TimetableSurfaceStyles`), forest-green ledger accent on a warm off-white canvas, muted semantics, tabular numbers.

### Palette
| Role | Token | Value |
|---|---|---|
| Ink (headings) | `tt.ink.strong` | `#0a1f1a` / white |
| Body | `tt.ink.base` | `#1a4d42`/70 / white/60 |
| Secondary | `tt.ink.muted` | `#1a4d42`/55 / white/45 |
| Tertiary | `tt.ink.faint` | `#1a4d42`/40 / white/35 |
| Accent | `tt.accent` / `tt.accentBtn` | `#246a59` / ink fill |
| Canvas | `tt.pageBg` | `#f3f7f5` / `#071411` |
| Panel | `tt.panel` / `tt.panelMuted` | white / `#f8fbfa` (+ `#0c1a17` dark) |
| Rule | `tt.border.hair` / `.soft` / `.row` | `#1a4d42`/10–12 |

### Type scale (the only sizes allowed)
`tt.text.micro` 10 · `caption` 11 · `small` 12 · `body` 13 · `title` 14 · `display` 17 · `metric` 24 (all include leading). Semantic tones stay red/amber/emerald; subject/class tints come from `getSubjectAccent` / `getGradeStreamAccent` and are intentionally outside the neutral scale.

### Rules
1. Type comes from `tt.text`. No one-off `text-[Npx]`.
2. Neutrals come from `tt.ink`, never slate/zinc/gray.
3. Dividers and borders come from `tt.border`.
4. Numeric readouts get `tt.numeral` (tabular-nums).
5. Interactive elements get `tt.focus`; icon buttons use `tt.iconBtn`.
6. Primary/selected actions use the forest accent (`tt.accentBtn`, `bg-[#0a1f1a]`), not ad-hoc colors.

### Status
Applied across the chrome: page shell/toolbar, health panel, journey, conflicts, subject insights, share drawer, inspector rail, all dialogs, the setup wizard + planner + auto-fill drawer, the mobile toolbar, class sidebar/drawer/context bar, workload/summary/search, and the bulk drawers.

**Deliberate exception:** the dense data grid (`AdminTimetableGrid`) and its skeleton keep a neutral zinc surface with ≤10px micro type. That's an intentional "neutral data plane inside a tinted shell" choice — everything around it is on tokens.

### Resizable columns (data grid)

Desktop admins can widen any column in the grid — useful when editing the last period of the week, where the day columns get cramped. 

**Where:** `components/AdminTimetableGrid.tsx` (desktop only; mobile keeps the day-tabs layout).

| Column | Default | Min | Max |
|---|---|---|---|
| Time rail ("When") | 120px | 88px | 280px |
| Day columns | 96px | 60px | 420px |

**Interaction**
- **Drag** the hairline handle on a header's right edge. Hovering anywhere on the header reveals that column's grip (so it's discoverable without always-on chrome); it stays bright while dragging and is visible when focused.
- **Double-click** a handle to reset that column to its default.
- **Keyboard:** focus a handle and use `←`/`→` to nudge 8px (`Shift` = 24px); `Home` or `Enter` resets.

**Accessibility:** each handle is a `role="separator"` with `aria-orientation="vertical"`, `aria-valuenow`/`min`/`max`, `tabIndex=0`, and a `Resize <column> column` label.

**How it lays out:** the desktop table renders a `<colgroup>` with a `<col>` per column and `table-auto md:table-fixed`; the table's inline `width` is the sum of the column widths with `minWidth: 100%`. The wrapper is `overflow-x-auto`, so widening past the viewport — including the last column — reveals horizontal scroll and yields more editing space rather than squashing neighbours.

**Persistence:** widths are saved to `localStorage` under the `columnWidthStorageKey` prop, hydrated on mount and written on change (the initial mount write is skipped). The combined view and the class view use separate per-school keys (`timetable-column-widths-<subdomain>-all` / `-class`), so each keeps its own layout. This is per-device, not per-account.

Cell padding and type in the grid are small/rem-based, so widening a column increases the breathing room around the same content; row heights (`min-h`) stay fixed.

### Resizable auto-fill drawer

The docked **Auto-fill timetable** drawer (`components/TimetableAutoGenerateDrawer.tsx`, desktop `lg+`) has the same drag treatment on its **left edge**: drag to widen/narrow (360–720px, default 424), double-click to reset, `←`/`→` to nudge 8px (`Shift` = 24px), `Home`/`Enter` reset. Widening it un-truncates subject names and gives the subject/lessons/doubles/teacher rows room to breathe. Width persists per device under `timetable-autofill-dock-width` in `localStorage`. The mobile/tablet `Sheet` path is unchanged.

## Validation plan

- **Per phase:** run the existing suite (`utils/allocationPreflight.test.ts` + project tests); manual pass of the acceptance criteria above on a 360×640 viewport and a 1280px desktop.
- **Phase 1 specifically:** screenshot the health pill, share drawer, journey stop, and meter at 0% / 60% / 90%+clashes / 100% — all four surfaces must agree at each state.
- **Regression watch:** lesson add → edit → move → delete → undo on both mobile drawer and desktop panel paths.
- **Update `TIMETABLE_UX_REVIEW.md`** backlog as items ship (its convention: strikethrough shipped items).

## Suggested order

Phase 0 → 1 → 2 → 3 → 4 → 5. Phase 0 is trust-critical and cheap; Phase 1 unblocks consistent copy everywhere else; Phases 2–4 are independent enough to parallelize across contributors once 1 lands; Phase 5 last so nothing gets resurrected mid-refactor.
